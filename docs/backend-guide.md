# 后端入门文档

这份文档专门按“前端工程师看后端”的思路来写，你不用先懂太多后端概念，也可以顺着看明白这个项目是怎么跑起来的。

## 1. 这个项目到底做了什么

这套系统现在已经把核心链路串起来了：

1. 定时或手动抓取热点。
2. 把热点存进本地 SQLite 数据库。
3. 针对某条热点做跨平台信息汇总。
4. 按你配置的个人风格生成稿件。
5. 手动编辑稿件并保存历史版本。
6. 绑定多个发布账号，创建立即发布或定时发布任务。
7. 记录发布结果，并做基础统计。

当前版本为了保证你能先把系统跑通，抓取和发布适配器采用“模拟实现 + 可扩展接口”的方式。

意思是：

- 系统流程是真的。
- 数据库存储是真的。
- 页面交互是真的。
- 定时任务是真的。
- 真实平台对接点也预留好了。
- 但抖音/小红书/网易号/搜狐号这些平台的真实接口，你后面需要按你手里的官方能力或合规能力继续接进去。

## 2. 技术栈为什么这样选

后端我故意没有选太重的框架，而是用：

- Node.js
- Express
- TypeScript
- SQLite

这样做的原因：

- 你本来就是前端工程师，Node/TS 语法最容易上手。
- Express 足够轻，文件结构清楚，不会一上来就被装饰器、模块系统绕晕。
- SQLite 是本地单文件数据库，不需要你额外装 MySQL，非常适合早期开发。

## 3. 项目目录怎么理解

### 根目录

- `package.json`：前后端工作区入口。
- `README.md`：项目总说明。
- `docs/backend-guide.md`：就是你现在看的这份文档。
- `docs/api-overview.md`：接口清单。

### 后端目录 `apps/server`

- `src/index.ts`：后端启动入口。
- `src/app.ts`：Express 应用配置。
- `src/routes/index.ts`：所有 HTTP 接口。
- `src/services`：业务逻辑核心。
- `src/adapters`：平台适配器。
- `src/config/database.ts`：SQLite 初始化和建表。
- `src/config/scheduler.ts`：定时抓取、定时发布、刷新统计。
- `src/data/mockPlatformData.ts`：模拟热点数据。
- `src/shared`：工具函数，比如加密、JSON、热度计算、文本处理。
- `.env.example`：环境变量示例。

## 4. 后端启动流程

当你执行后端启动命令后，流程是这样的：

1. `src/index.ts` 被执行。
2. `bootstrapDatabase()` 先跑数据库建表和默认数据初始化。
3. `createApp()` 创建 Express 应用。
4. 监听 `3000` 端口。
5. `startScheduler()` 启动定时器。

也就是说，这个项目启动后会自动具备：

- 数据表自动创建
- 默认抓取配置自动写入
- 默认风格模板自动写入
- 定时抓取热点
- 扫描并执行到点的发布任务
- 自动刷新发布统计

## 5. 数据是怎么流动的

### 5.1 抓热点

前端点击“立即抓取”后，请求：

- `POST /api/crawler/run`

后端执行：

- 读取抓取配置 `crawlConfig`
- 调用 `sourceRegistry` 里的平台适配器
- 拿到热点数据
- 过滤关键词、屏蔽词、屏蔽账号
- 计算热度和质量分
- 写入 `hotspots` 表

### 5.2 汇总热点

前端点击“汇总”后，请求：

- `POST /api/hotspots/:id/aggregate`

后端执行：

- 根据热点标题做关键词
- 让所有平台适配器去查相关内容
- 去重、合并
- 提炼核心事实
- 保存到 `hotspot_aggregations` 表

### 5.3 生成稿件

前端点击“生成稿件”后，请求：

- `POST /api/drafts/generate`

后端执行：

- 读取热点信息
- 读取热点汇总信息
- 读取风格模板
- 自动生成 3-5 个标题候选
- 自动拼接正文结构
- 自动生成配图列表
- 自动估算原创度
- 自动做基础问题检测
- 保存到 `drafts`
- 同时写入 `draft_versions`

### 5.4 发布稿件

前端创建发布任务后，请求：

- `POST /api/publish/jobs`

后端执行：

- 校验稿件是否存在
- 保存发布任务到 `publish_jobs`
- 保存每个平台目标到 `publish_targets`
- 如果是立即发布，直接执行
- 如果是定时发布，等定时器扫描到时间后执行

### 5.5 统计数据

后端会读取 `publish_targets` 表里成功发布的数据，按平台聚合出：

- 发文数
- 阅读量
- 点赞量
- 评论量
- 转发量

## 6. 数据库表怎么理解

### `app_settings`

系统配置表。

主要存：

- 抓取配置
- 生成配置
- 上次抓取时间

### `hotspots`

热点主表。

一条记录代表一条抓到的热点。

字段重点：

- `platform`：来自哪个平台
- `topicType`：科技/民生/娱乐等
- `title` / `content` / `summary`
- `publishTime`
- `likeCount` / `commentCount` / `shareCount`
- `heatScore`：热度分
- `status`：待处理 / 已处理 / 忽略

### `hotspot_aggregations`

热点汇总表。

一条热点通常对应一条汇总结果。

### `styles`

个人风格模板表。

你以后可以在这里维护多个账号、多种文风。

### `drafts`

稿件主表。

就是最终在编辑器里看到的稿件。

### `draft_versions`

稿件历史版本表。

每次生成或手动保存，都会新增一条历史版本。

### `publish_accounts`

发布账号表。

账号凭证会被加密保存。

### `publish_jobs`

发布任务表。

表示“这篇稿什么时候发布”。

### `publish_targets`

发布目标表。

表示“这篇稿发到哪些平台、用哪个账号、结果怎么样”。

## 7. 你最需要理解的 3 个后端层

### 7.1 Route 层

在 `src/routes/index.ts`。

它的职责很简单：

- 接前端请求
- 调用 service
- 返回 JSON

你可以把它理解成前后端之间的门。

### 7.2 Service 层

在 `src/services`。

这是整个后端最核心的地方。

比如：

- `hotspotService.ts`：抓热点、查热点、汇总热点
- `draftService.ts`：生成稿件、保存稿件、版本回溯
- `publishService.ts`：发稿、定时执行、刷新数据

如果以后你想改业务规则，优先改 service。

### 7.3 Adapter 层

在 `src/adapters`。

它的职责是“适配不同平台”。

比如抓热点时：

- 抖音一个接口方式
- 小红书一个接口方式
- 微博一个接口方式

发布时也是一样。

所以我把平台差异封装在 adapter 里，这样你以后接入真实平台时，不用改整个系统，只改对应适配器就行。

## 8. 真实平台应该从哪里接入

### 8.1 接真实抓取

重点改这里：

- `apps/server/src/adapters/sourceAdapter.ts`

你现在看到的是 `MockSourceAdapter`。

以后你可以新增：

- `DouyinApiAdapter`
- `XiaohongshuAdapter`
- `WeiboAdapter`

然后把 `sourceRegistry` 中对应的平台实现替换掉。

### 8.2 接真实发布

重点改这里：

- `apps/server/src/adapters/publisherAdapter.ts`

现在是 `MockPublisherAdapter`。

以后如果你拿到了某个平台的真实发布能力，就把这里改成：

1. 从加密凭证里取 cookie/token/accessToken。
2. 调用真实发布接口。
3. 把返回的文章 ID、状态、错误信息写回数据库。

## 9. 账号凭证为什么要加密

发布账号如果直接明文存数据库，很容易泄露。

所以我在：

- `src/shared/crypto.ts`

里做了一个简单的对称加密。

环境变量：

- `APP_SECRET`

这个值你后面一定要改，不要用默认值。

## 10. 如何安装和运行

先说明一下：我当前这个编码环境里没有现成 Node 运行时，所以代码我已经完整搭好了，但没法在这里直接替你执行 `npm install` 和启动。你在自己电脑上只需要按下面步骤走。

### 10.1 安装 Node.js

建议安装：

- Node.js 20 LTS

安装好后，确认命令可用：

```bash
node -v
npm -v
```

### 10.2 安装依赖

在项目根目录执行：

```bash
npm install
```

### 10.3 配置后端环境变量

把下面文件复制为 `.env`：

- `apps/server/.env.example`

内容类似：

```env
PORT=3000
DB_PATH=./storage/app.db
APP_SECRET=please-change-me
```

### 10.4 启动后端

```bash
npm run dev:server
```

默认地址：

- `http://localhost:3000`

### 10.5 启动前端

另开一个终端：

```bash
npm run dev:web
```

默认地址：

- `http://localhost:5173`

## 12. 你后面优先可以继续做什么

如果你想把这个项目继续做实，我建议下一步按这个顺序：

1. 先把 Node 环境装好，跑通现在这套前后端。
2. 把模拟抓取换成你能拿到的真实、合规数据源。
3. 把模拟发布换成真实平台发布能力。
4. 接入大模型 API，让稿件生成从模板式升级成真正 AI 写稿。
5. 增加登录鉴权、RBAC 权限、操作日志。
6. 把 SQLite 升级到 MySQL/PostgreSQL，方便多人协作。

## 13. 你作为后端小白最容易卡住的点

### 为什么我点按钮没反应

先看两个服务有没有都启动：

- 前端 `5173`
- 后端 `3000`

### 为什么接口 500

先看后端终端报错。

重点看：

- JSON 凭证有没有写错
- 数据表有没有初始化
- 环境变量有没有配置

### 为什么能创建发布任务但没立刻发布

因为如果你选了未来时间，它会进入定时任务队列，等 `scheduler` 每分钟扫描时执行。

### 为什么发布结果是“模拟发布”

因为当前阶段我先帮你把系统和架构搭好了，真实平台发布能力需要你按实际资源继续接入。

如果你愿意，我下一步可以继续直接帮你做两件事里的任意一个：

1. 把这套项目再补一版“登录鉴权 + 用户管理 + 菜单权限”。
2. 继续把“AI 写稿”这块接成 OpenAI 兼容接口版本。
